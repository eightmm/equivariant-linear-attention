# Static Cartesian CTP-LGL study (2026-07-27)

## Decision

The implementation is retained as an opt-in research capability, but it does
not replace the current gated-plus-grouped LGL. The native Cartesian
tensor-product path passed its mathematical, compatibility, gradient, and
real-batch resource gates. It then failed the preregistered ATOM3D-LBA ID30
accuracy promotion rule.

This is a useful negative result: direct local tensor products consistently
recover part of the cost of carrying persistent `2e` state, but the extra
state and coupling do not beat the simpler current scalar/vector candidate at
this data scale and fixed training budget.

## Implemented scope

The public model remains `EquivariantAttention`. The new opt-in configuration
is:

```python
EquivariantAttentionConfig(
    hidden_irreps="64x0e + 4x1o + 4x2e",
    num_heads=4,
    local_head_counts=(4, 0, 4),
    use_gated_local_transport=True,
    use_grouped_invariant_normalization=True,
    use_cartesian_tensor_product_local_transport=True,
    use_static_tensor_carrier=True,
    cartesian_tensor_product_local_layers=(2,),
)
```

It statically enables three native Cartesian paths:

```text
2e x 1o -> 1o:  T_j d_ij
2e x 0e -> 2e:  T_j
1o x 1o -> 2e:  ST(v_j outer d_ij)
```

The invariant gate receives receiver/sender tensor contraction, receiver/edge
quadrupole contraction, sender/edge quadrupole contraction, and the two tensor
norms. The final gate projection starts at zero, so the initial CTP function
matches the persistent-`2e` control. The compact carrier is projected once per
node, updated only at local stages, carried unchanged through the middle global
stage, and fully consumed only by the final local stage.

At fixed width the global block remains exact fixed-rank `O(N)` and the local
path is `O(E)`. No `N x N` attention tensor, neighbor triplets, learned
Cartesian vector, spherical harmonics, or new dependency is introduced.

This packet is deliberately not an arbitrary-irrep implementation. It supports
only `0e`, polar `1o`, and reflection-even symmetric-traceless `2e`. Parity-odd
irreps and `l>2` remain rejected.

## Mathematical and software verification

Focused checks cover:

- exact disabled-path/state-schema compatibility and zero-initialized
  persistent-control equality;
- direct sensitivity to sender tensor state;
- finite nonzero gradients into the new path;
- float64 rotations and reflections under full `O(3)`;
- translation, node permutation, edge-order, batch-isolation, and cutoff
  behavior;
- public configuration validation and per-layer scheduling.

The repository fast gate before the final documentation pass reported
595 passing tests at 88.53% coverage, plus clean Ruff, compileall, and ML
smoke checks. The final post-documentation gate reported 596 passing tests at
the same 88.53% coverage, plus clean Ruff, compileall, and CPU float64 ML
smoke checks.

## Resource gate

The authoritative resource comparison used an isolated fresh process per arm
to avoid the arm-order drift observed in the original sequential timer.
Every arm used the same cached real LBA batch:

- 16 complexes;
- 7,378 nodes;
- 153,029 directed candidate edges;
- strict float32 CUDA on an NVIDIA RTX PRO 6000 Blackwell Max-Q Workstation
  Edition;
- 3 warmup and 30 synchronized timed full training steps.

| ratio, CTP/current candidate | observed | ceiling | result |
|---|---:|---:|---|
| trainable parameters | 1.001570 | 1.10 | pass |
| median synchronized train step | 1.134213 | 1.25 | pass |
| peak CUDA allocation | 1.150459 | 1.25 | pass |

The earlier sequential measurement reported a misleading `1.417x` latency
ratio while its device-stage profile and a short independent timer were near
`1.17x`. The sequential artifact is retained; the isolated fresh-process
measurement is authoritative because it removes arm-order contamination.

## Seed-44 rejection screen

The first full-ID30 screen used seed 44, 20 epochs, 4,400 updates per arm, and
the same 32,303,245-edge topology for all arms.

| arm | best validation RMSE (pK) |
|---|---:|
| current candidate | 1.618507 |
| persistent `2e` only | 1.620669 |
| persistent `2e` + CTP | **1.606039** |

CTP improved the current and persistent controls by `0.012468` and
`0.014630 pK`, respectively. This passed the rejection screen and admitted the
fixed multi-seed confirmation. It did not itself satisfy the final
`0.020 pK` promotion threshold.

- official ATOM3D-LBA ID30 train/validation split;
- 3,507 train and 466 validation complexes;
- train-only target normalization;
- seeds 41, 42, and 43 for model initialization and data order;
- 35 epochs and 5,145 updates per arm;
- batch size 24 for every arm;

The promotion rule required all resource gates, mean gain of at least
`0.020 pK` over current, positive mean gain over persistent-only, at least two
of three current-candidate paired wins, and no regression worse than
`0.050 pK`.

The CTP arm passed the resource, persistent-control, and worst-regression
criteria. It failed the primary mean-gain criterion and had `0/3` paired wins.
Promotion is therefore rejected.

The confirmation itself consumed 2,276.31 seconds. The seed-44 screen consumed
694.74 seconds; the bounded resource probes and failed queue attempt stayed
inside the remaining approved compute envelope. All nine registered
confirmation runs completed, and no test labels were evaluated.

## Interpretation

Three facts are separated:

1. The tensor-product operator is real and active: it passes direct
   sensitivity, gradient, and transformation checks.
2. It is implementable at acceptable cost: the real-batch resource ceilings
   all pass.
3. It is not a better default for this LBA protocol: every paired seed is
   worse than the simpler candidate.

The persistent-only control is essential. Without it, the seed-44 result could
be mistaken for evidence that tensor state alone helped. In the confirmation,
persistent `2e` is worse than current by `0.021304 pK` on average; CTP recovers
roughly half of that gap but not all of it. This suggests the main bottleneck is
not the absence of these three local Clebsch--Gordan-like paths. It is more
likely the optimization burden and fixed-width allocation introduced by
carrying tensor state, or the fact that this affinity feature/task regime does
not require persistent quadrupolar state at every node.

The next architecture step should therefore not be “add arbitrary higher
`l` everywhere.” A higher-order backend would add larger constants before
there is evidence that `2e` pays for itself. If revisited, the smallest
disconfirming direction is sparse/conditional tensor state: create `2e` only
at interface nodes or final refinement, couple it directly into scalar
content/readout, and compare it to a parameter-matched scalar/vector expansion.
That is a new experiment, not part of this result.

## Evidence boundary

This is same-harness, warm ID30 validation evidence using bound-complex
coordinates and unchanged atom/segment features. It is not a cold-target,
pose-robustness, sequence-to-structure, test-set, official Equiformer, or
published-model superiority result. The feature schema was identical across
arms, so the paired effect is attributable to architecture within this
harness; it does not show that the current biochemical representation is
optimal.
